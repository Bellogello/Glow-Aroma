Getting started

Local setup

Get GlowAroma running on your machine in under 10 minutes.

Prerequisites

Node.js 18+ npm MySQL 8+ or MariaDB Git

Install dependencies

# Backend
cd Glow-Aroma
npm install

# Frontend
cd client && npm install

# Required extras
npm install recharts
npm install @react-three/fiber @react-three/drei

Database setup

Export from Railway (production) and import locally:

# Export from Railway
mariadb-dump -h monorail.proxy.rlwy.net -P 22983 \
  -u root -p --ssl-verify-server-cert=FALSE \
  railway > glow_aroma_db.sql

# Create local DB and import
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS glow_aroma_db;"
mysql -u root -p glow_aroma_db < glow_aroma_db.sql

Run locally

# Terminal 1 — backend on :8080
node server.js

# Terminal 2 — frontend on :5173
cd client && npm run dev
Set VITE_API_URL=http://localhost:8080 in client/.env so the frontend points to your local backend.

Switch between local and production DB

Change these two values in .env to toggle:

VariableLocalProduction
DB_HOSTlocalhostmonorail.proxy.rlwy.net
DB_PORT330622983
DB_NAMEglow_aroma_dbrailway
NODE_ENVdevelopmentproduction
NODE_ENV controls SSL on the DB connection — disabled locally, enabled on production.

Architecture

Authentication

JWT-based auth with Google OAuth and role-based access control.

JWT flow

On login or register the backend returns a JWT signed with JWT_SECRET (7-day expiry). The frontend stores userId, userName, roleId, and token in localStorage. No Authorization header is used — userId is passed in request bodies.

Google OAuth

Frontend uses @react-oauth/google. On success it sends access_token to POST /auth/google. Backend calls Google userinfo API, looks up or creates the user, and returns the same JWT structure as regular login.

Role-based access

role_idRoleAccess
1CustomerPublic routes + own cart, orders, profile, addresses
2AdminDashboard, orders, products, inventory, messages, store settings
3Super AdminAll admin access + staff management + promo code management
Legacy accounts with plain-text passwords are handled: if password_hash does not start with $2 it is compared as plaintext before bcrypt is used.

Password hashing

// Hash on register
const hashed = await bcrypt.hash(password, 10);

// Verify on login
const match = await bcrypt.compare(password, user.password_hash);

Frontend

3D rendering system

Two separate renderers for different use cases — a full configurator and a lightweight display viewer.

CandlePreview3D props

PropTypeDescription
modelUrlstringURL to .glb file. Falls back to /candle.glb if not set.
cupColorstringRGBA or hex color for glass cup mesh.
waxColorstringHex color for wax fill mesh.
layerColorsstring[]Hex colors for mold layer meshes.
cupSizestringsmall / medium / large — scales entire model.
colorablePartsstring[] or JSON stringMesh names for mold layers from candle_models.colorable_parts.
flatShadingbooleanEnables flat shading on all materials.
refforwardRefExposes getSnapshot() → base64 PNG string.

Mesh detection — CandlePreview3D

Mesh name patternTreated as
ends with _0 or includes cylinder_0Glass cup — MeshPhysicalMaterial, transparent
ends with _1, includes wax or sphereWax fill
ends with _2, includes wickWick — no color change
name in colorable_parts arrayMold layer at that array index

Mesh detection — MiniCandleViewer

Collects all non-wick, non-glass meshes in traversal order. Assigns layers[index] by position — so Wax_Bottom gets layers[0], Wax_Middle gets layers[1], Wax_Top gets layers[2].

Model requirements

  • 1Model in Blender. Name meshes clearly — Wax_Bottom, Wax_Middle, Wax_Top for molds.
  • 2Export as glTF Binary (.glb).
  • 3Upload via Dashboard → 3D Models. Stored on Cloudinary as resource_type: "raw".
  • 4Set colorable_parts JSON array of mesh names in layer order for mold models.
If colorable_parts is empty or null for a mold model, all layers will receive the same primary color. Always set this field in the inventory for mold type models.
Integrations

Paymob integration

Three-step API flow for EGP card payments via iframe.

Payment flow

  • 1Auth token — POST to Paymob /auth/tokens with PAYMOB_API_KEY → returns authToken.
  • 2Register order — POST to Paymob /ecommerce/orders with amount, merchant_order_id → returns paymobOrderId.
  • 3Payment key — POST to Paymob /acceptance/payment_keys with billing data → returns paymentToken.
  • 4Show iframe — Frontend renders https://accept.paymob.com/api/acceptance/iframes/{iframeId}?payment_token={paymentToken}.
  • 5Callback — Paymob POSTs to /paymob/callback. Backend verifies HMAC-SHA512 → updates order status_id = 2.

HMAC verification

18 fields concatenated in a fixed order, then signed with HMAC-SHA512 using PAYMOB_HMAC_SECRET. If data.success !== true or HMAC fails, the order is NOT updated.

const fields = [
  'amount_cents', 'created_at', 'currency', 'error_occured',
  'has_parent_transaction', 'id', 'integration_id', 'is_3d_secure',
  'is_auth', 'is_capture', 'is_refunded', 'is_standalone_payment',
  'is_voided', 'order', 'owner', 'pending',
  'source_data.pan', 'source_data.sub_type',
  'source_data.type', 'success'
];
Integrations

Socket.io — live viewers

Real-time viewer count per product page. Badge appears when count ≥ 2.

Events

EventDirectionPayloadDescription
join_productClient → ServerproductId (string)Join room, increment count
leave_productClient → ServerproductId (string)Leave room, decrement count
update_viewersServer → Clientcount (number)Broadcast new count to room
disconnectAuto—Server decrements via socketRooms map

Server state

const viewersCount = {};  // { "5": 3, "12": 1 }
const socketRooms  = {};  // { "socket_abc": "5" }
socketRooms is needed because socket.rooms is cleared before the disconnect handler fires — without it you can't decrement the correct product's count on disconnect.

Frontend pattern

useEffect(() => {
  const socket = io(API_BASE_URL);
  socket.emit('join_product', String(id));

  socket.on('update_viewers', (count) => setViewers(count));

  return () => {
    socket.emit('leave_product', String(id));
    socket.disconnect();
  };
}, [id]);

Deployment

Deploy guide

Frontend on Vercel, backend + database on Railway.

Frontend — Vercel

  • 1Connect your GitHub repo to Vercel.
  • 2Set root directory to client, build command npm run build, output dist.
  • 3Add environment variables in Vercel dashboard: VITE_API_URL and VITE_GOOGLE_CLIENT_ID.

Backend — Railway

  • 1Connect GitHub repo to Railway.
  • 2Set start command to node server.js.
  • 3Add all backend env variables in Railway Variables panel.
  • 4Set NODE_ENV=production to enable DB SSL.
Railway sets PORT automatically. The server must bind to 0.0.0.0 not localhost.
// server.js — correct binding
server.listen(PORT, '0.0.0.0', () => {
  console.log(`Server listening on port ${PORT}`);
});

DB SSL config

const db = mysql.createConnection({
  host:     process.env.DB_HOST,
  user:     process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  port:     process.env.DB_PORT || 3306,
  ssl: process.env.NODE_ENV === 'production'
    ? { rejectUnauthorized: false }
    : false
});

Known issues

Gotchas and quirks to be aware of when working on GlowAroma.

AreaIssue
cup_color_idStores RGBA string — not a FK to cup_colors. Cart name resolved by parsing cup_shapes.colors JSON in Node.js.
cup_sizeStores ml integer directly — not a FK to cup_sizes table.
Snapshot storageBase64 PNG stored in LONGTEXT. Consider compressing to JPEG 0.6 to reduce payload and DB size.
colorable_partsMust be set manually per mold model in inventory. If empty, all mold layers receive the same primary color.
Route order/admin/orders/:id/items MUST be registered before /admin/orders/:orderId in server.js.
Admin showcase fetchfetchDashboardData uses /showcase (public — only active). Use /admin/showcase to show hidden designs in admin view.
MiniCandleViewer layerslayers prop must be a parsed array, not raw JSON string. CreateYourOwnCard parses layers_json before passing.
Paymob statusCallback sets status_id = 2. Currently no dedicated "Paid" status — Shipped and Paid share the same value.
express.json limitSet to 10mb for snapshot payloads. Increase if large images cause 413 errors.
Server timeoutserver.timeout set to 120000ms. Large snapshot uploads or slow Railway cold starts may still time out.
